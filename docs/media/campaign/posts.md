# BLADE 1.2 LinkedIn campaign

Seven portrait posts (1080×1350) plus a news item for the university or
group website. Cards are generated by `make_cards.py` and rendered with
`render.js`:

```bash
uv run python docs/media/campaign/make_cards.py
NODE_PATH=$(npm root -g) node docs/media/campaign/render.js
```

Suggested rhythm: post 1 on release day, then one post every two to three
working days (Tuesday to Thursday mornings work best on LinkedIn). Put links
in the post text; LinkedIn does not penalise them much any more, but if
reach matters, move the link to the first comment.

## 2 / 7 — YAML experiments (`card-02-yaml.png`)

From idea to benchmark in four commands.

Setting up a fair comparison of algorithm design methods used to mean a
custom script per experiment. In BLADE 1.2 an experiment is a single YAML
file: which LLMs, which methods, which problems.

`iohblade init` writes a starting point, `validate` checks the file
without running anything, `check` does a smoke test without a single LLM
call, and `run` starts the experiment. Built-in problems, methods and LLMs
are referred to by name; your own problem or method is a Python file next
to the configuration.

The point: an experiment you can share, review and rerun, instead of a
script only its author understands.

Docs: https://xai-liacs.github.io/BLADE/yaml_experiments.html

## 3 / 7 — Default suites (`card-03-suites.png`)

Benchmarks with fixed settings, ready to run.

Results on "BBOB" are only comparable if everyone uses the same functions,
instances, dimension and budget. BLADE 1.2 ships named suites where those
choices are made for you:

🔸 `bbob_groups`: the five BBOB function groups as separate benchmarks,
instances 1–5 for training and 6–15 for testing, 10-D, budget factor 2000
🔸 `bbob`: the 24 BBOB functions one by one, instances 1–10 for training
and 11–30 for testing
🔸 MA-BBOB: 25 training and 50 test instances
🔸 17 AlphaEvolve mathematical problems (packing, Heilbronn,
auto-correlation, ...)
🔸 combinatorial problems: Steiner trees, TSP, CVRP, graph colouring

`quick` gives a small set to try a setup, `default` combines the BBOB
groups, the maths and the combinatorial problems, and `full` runs
everything. One
`dim` and `budget_factor` set the BBOB and MA-BBOB parts; the other
problems keep their own fixed settings.

Overview with run-time estimates: https://xai-liacs.github.io/BLADE/benchmarks.html

## 4 / 7 — Methods (`card-04-methods.png`)

Nine methods. One fair harness.

LLaMEA, EoH, ReEvo, FunSearch, ShinkaEvolve, LHNS, MCTS-AHD, MoEH and
random search all run inside BLADE, on the same terms:

✅ the same number of evaluations per method
✅ the same LLM and the same problems
✅ the same isolated evaluation of every generated algorithm

FunSearch and ShinkaEvolve are new in 1.2, reimplemented so they run with
any LLM that BLADE supports. Random search is in the list on purpose:
every method should beat it.

Have a method of your own? Implement one class and it runs next to the
others.

https://github.com/XAI-liacs/BLADE

## 5 / 7 — Local LLMs (`card-05-local-llms.png`)

Run it on your own GPUs.

LLM-driven algorithm design needs thousands of LLM calls. With open models
such as Qwen or DeepSeek served by Ollama, vLLM or LM Studio, you pay for
electricity instead of tokens, and your experiments stay reproducible
because the model does not change under you.

The pattern on the card: one vLLM server per GPU, combined with
`provider: multi`, so parallel runs share the servers. One configuration
file, no code changes.

https://xai-liacs.github.io/BLADE/yaml_experiments.html

## 6 / 7 — Analysis (`card-06-analysis.png`)

See what the LLM actually designed.

A final score tells you which method won. It does not tell you why. BLADE
keeps every generated algorithm: its code, its prompt, its score and its
parent. That lets you look at:

📈 convergence and test scores per run
📊 methods compared across seeds
🌳 code evolution: which algorithm came from which
🔍 the code itself, in the browser with `iohblade-webapp`

For us, this is where explainability meets automated algorithm design:
understanding what the search produced, not just how well it scored.

A public leaderboard is coming soon.

https://github.com/XAI-liacs/BLADE

## 7 / 7 — Coding agents (`card-07-coding-agents.png`)

Set up a benchmark by asking your agent.

`iohblade skill` installs a skill that teaches coding agents how BLADE
works: the YAML format, the commands, how to write a problem or method,
and how to read the errors.

Ask Claude Code, or another agent that reads skills, to "benchmark my
scheduling heuristic problem with LLaMEA and ShinkaEvolve on a local Qwen
model, 5 runs each" and it writes the problem file and the experiment,
validates and checks them, and hands you the command to start.

That wraps up this series on BLADE 1.2. Questions, feature requests and
new benchmark problems are very welcome on GitHub.

https://github.com/XAI-liacs/BLADE

## News item (university / group website)

**BLADE 1.2: a benchmark suite for LLM-driven algorithm design**

Large language models can now write and iteratively improve optimisation
algorithms. Methods such as LLaMEA, FunSearch, EoH and ShinkaEvolve use
an LLM to generate candidate algorithms, evaluate them, and feed the
results back into the next generation. As the number of such methods
grows, so does the need for a fair way to compare them.

BLADE (Benchmarking LLM-driven Automated Design and Evolution), developed
at LIACS, provides that comparison. Version 1.2, released today, makes it
considerably easier to use:

- **Experiments as configuration.** An experiment is described in a
  single YAML file and checked before any LLM is called.
- **Nine built-in methods**, including newly added reimplementations of
  FunSearch and ShinkaEvolve that run with any supported LLM.
- **Default benchmark suites** with fixed training and test instances:
  the BBOB function groups, MA-BBOB, 17 mathematical problems from
  AlphaEvolve, and combinatorial problems.
- **Hosted and local LLMs**, from OpenAI, Anthropic and Google to open
  models served on local GPUs with Ollama or vLLM.
- **Analysis tools** that keep every generated algorithm with its code,
  score and lineage, so researchers can study what was designed, not
  only how well it performed.
- **Support for coding agents**, which can set up and check experiments
  on a user's behalf.

BLADE is open source and available on PyPI as `iohblade`.
