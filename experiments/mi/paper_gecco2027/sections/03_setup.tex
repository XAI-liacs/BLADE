\section{Experimental Setup}\label{sec:setup}

\paragraph{Loop and main problem.}
We run \llamea with 4 parents and 12 offspring per generation, elitist
selection, and its three mutation prompts (\emph{refine} a parent,
write a \emph{new} algorithm, \emph{simplify} a parent). A run evaluates
100 generated algorithms unless stated otherwise. The main problem is
MA-BBOB~\cite{vermetten2025mabbob} in 5-D on 10 training instances, with
a budget of $2000\cdot D$ function evaluations; the fitness is the area
over the convergence curve (\aocc) of the best-so-far log-precision in
$[10^{-8},10^{2}]$, averaged over instances. \blade's MA-BBOB scores a
generated algorithm that overspends its budget with 0; in a pilot, 84\%
of the algorithms did so, which collapses the fitness labels. We
therefore truncate the run at the budget instead.

\paragraph{Transfer problems.}
To test transfer we use four problems that the probes and directions
were not derived from. Mini-Bragg is a 10-layer photonic reflector from
\blade; circle packing places $n=26$ circles in the unit square and
scores the sum of radii after a feasibility repair. Three BBOB
functions~\cite{hansen2009bbob} in 20-D cover different landscapes: f2
(separable ill-conditioned ellipsoid), f9 (rotated Rosenbrock) and f20
(Schwefel, multimodal with weak global structure). Each function is its
own campaign with budget $2000\cdot D$ and \aocc on the log regret. We
widen the upper bound of the \aocc window per function ($10^{3}$,
$10^{8}$ and $10^{6}$ for f20, f2 and f9) so that working code is not
scored 0. Runs train on instances 10--14, and the final best algorithm
of each run is validated on 16 held-out instances (15--30). The prompt
does not describe the function: the model sees a black box.

\paragraph{Generator and instrumentation.}
The generator is Qwen3-8B~\cite{qwen3} with thinking disabled and
temperature 0.8; we replicate the reading results with Qwen3-14B and
Gemma-3-12B-it~\cite{gemma3}. A hooked wrapper around the model records
the residual-stream activations at every layer, for the prompt and for
the generated code, and can add steering vectors at chosen layers. All
generations are seeded, so counterfactual and steered generations are
compared with common random numbers.

\paragraph{Labels.}
For every generated algorithm we record whether it crashes (and the
exception type), whether it exceeds its budget, its fitness and whether
it improves on its parent. Algorithmic concepts (population, differential
evolution (DE), particle swarm, crossover, CMA-style covariance,
gradient, local search, restart, surrogate, elitism, step-size and
parameter adaptation, \dots) are labelled from code patterns; the set of
concepts of an algorithm defines its \emph{family}. Search behaviour is
measured from the traced evaluations of the generated
algorithm~\cite{blade2025}: exploration~\% (share of evaluations far from
the best so far), intensification and the time of the last improvement.
Code diversity is measured with CodeBLEU~\cite{ren2020codebleu}, AST
distance and the Jaccard distance of concept sets.

\paragraph{Sandbox fixes.}
While building the transfer problems we found issues that change the
failure statistics AAD papers report. \blade executes generated code with
separate global and local namespaces, which hides module-level imports
and helper functions from the algorithm's class (a \texttt{NameError}
at run time); some packages the prompts allow were missing (scipy and
scikit-learn for MA-BBOB, \texttt{six} for the photonics simulator); the
photonics \aocc window compressed every score into 0.20--0.28; and the
problem description was dropped from the \llamea prompt. Fixing the
namespace and the packages alone cuts the failure rate of one family of
generated initialisation code from 100\% to 29\%. All experiments use
the fixed sandbox.\todo{report to the benchmark maintainers and cite the
fix anonymously}
